# DiskSpaceManager (Phase 3)

검사기 PC의 검사 결과 로그(이미지·영상)를 보관 기간에 따라 자동으로 정리하는
백그라운드 상주 프로그램입니다. 시스템 트레이에서 상태를 확인하고 설정을 바꿉니다.

---

## 1. 준비물

| 항목 | 요구 사항 |
|---|---|
| OS | **Windows 전용** (레지스트리·트레이·Win32 API 사용) |
| Python | **3.10 이상** (3.14 에서 개발·검증) |
| tkinter | 파이썬에 포함. python.org 설치본이면 기본 포함 |
| 패키지 | `pystray`, `pillow`, `Send2Trash` — `requirements.txt` |

> Microsoft Store 판이나 일부 배포판은 tkinter 가 빠져 있을 수 있습니다.
> `python -c "import tkinter"` 로 먼저 확인하세요.

## 2. 내려받아 실행하기

```bat
git clone https://github.com/ChoiDDingHo/DiskSpaceManager.git
cd DiskSpaceManager

python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

:: 실행 (콘솔 창 없이 트레이에만 상주)
.venv\Scripts\pythonw.exe DiskSpaceManager.py
```

개발 중 로그를 콘솔에서 보고 싶으면 `python.exe` 로 실행하세요.
등록된 프로파일이 하나도 없으면 첫 실행 시 설정창이 자동으로 열립니다.

## 3. exe 로 빌드하기

검사기에 파이썬을 설치하지 않으려면 단일 exe 로 만들어 배포합니다.

```bat
.venv\Scripts\python.exe -m pip install pyinstaller

.venv\Scripts\python.exe -m PyInstaller --noconsole --onefile ^
  --name DiskSpaceManager ^
  --icon assets\app_icon.ico ^
  --add-data "assets;assets" ^
  DiskSpaceManager.py
```

`dist\DiskSpaceManager.exe` 가 만들어집니다 (약 19MB, 빌드 20초 내외).
**`--add-data` 를 빼먹으면** 트레이 아이콘이 기본 도형으로 대체됩니다.

exe 는 파이썬이 없는 PC에서도 그대로 실행되며, 설정과 로그는 똑같이
`%LOCALAPPDATA%\DiskSpaceManager\` 에 생깁니다.

| 설정... | 관리 폴더와 전역 설정 편집 |

| 색 | 의미 |
|---|---|
| 초록 | 정상 |
| 노랑 | 여유 공간 경고 기준 미만, 또는 직전 작업에 삭제 실패 발생 |

아이콘 원본은 `assets/tray_icon.png` 입니다. 이 파일을 바꾸면 트레이 아이콘이
바뀝니다(정사각형 PNG, 배경 투명 권장). 파일이 없으면 단순한 도형 아이콘으로
대체되며 프로그램은 정상 동작합니다.

## 5. 설정

### 관리 폴더(프로파일)

폴더 하나에 정책 하나입니다. **같은 폴더라도 파일 종류별로 프로파일을 나누면
보관 기간을 다르게 줄 수 있습니다.** 이것이 용량 확보의 핵심입니다.

| 항목 | 설명 |
|---|---|
| 대상 폴더 | 정리할 폴더. 드라이브 루트와 시스템 폴더는 등록이 거부됩니다 |
| 하위 폴더 포함 | 하위 트리 전체를 대상으로 할지 |
| 대상 패턴 | `*.jpg; *.png; *.mp4` — 세미콜론 구분 |
| 제외 패턴 | 파일명과 **폴더명 모두**에 적용. `NG` 를 넣으면 NG 폴더 전체를 보존 |
| 보관 기간 | 이 일수가 지난 파일이 대상. **최소 3일** (오입력 사고 방지) |
| 긴급 시 최소 보관 | 용량이 위험 수준일 때만 여기까지 지웁니다. 평소에는 절대 내려가지 않습니다. 보관 기간과 같게 두면 긴급 정리 대상에서 빠집니다 |
| 날짜 기준 | 수정 시각 / 생성 시각 / **폴더명 날짜** |
| 폴더명 날짜 형식 | 날짜 기준이 폴더명일 때. `%Y%m%d` → `20260922` |
| 처리 방식 | 영구 삭제 / 휴지통으로 이동 |
| 빈 폴더 정리 | 파일을 지운 뒤 비어 버린 날짜 폴더까지 제거 |
| 모의실행 | 이 프로파일만 삭제하지 않고 기록만 |

> **날짜 기준을 반드시 확인하세요.** 파일을 복사하거나 이동하면 수정 시각이
> 갱신됩니다. 실제로 40일 전 폴더의 파일이 "오늘 수정됨"으로 남아 정리되지
> 않는 경우가 흔합니다. 날짜별 폴더 구조(`20260922\...`)라면 **폴더명 기준**이
> 가장 정확합니다.

### 권장 프로파일 예시

| 프로파일 | 대상 패턴 | 제외 | 보관 | 긴급 하한 |
|---|---|---|---|---|
| 검사 영상 | `*.mp4; *.avi` | | 7일 | 3일 |
| 양품 이미지 | `*.jpg; *.png` | `NG` | 30일 | 7일 |
| 불량 이미지 | `*.jpg; *.png` | `OK` | 180일 | 180일 (긴급 정리 제외) |

긴급 정리는 **목록 위에서부터** 처리하므로, 먼저 지워도 되는 영상을 맨 위에 둡니다.
순서는 관리 폴더 탭의 `▲ 위로` / `▼ 아래로` 로 바꿉니다.

영상이 용량의 대부분을 차지하고 재사용 가치는 낮은 반면, 불량 이미지는 용량은
작지만 클레임 대응에 필요합니다. 이렇게 나누면 총 용량은 크게 줄면서 필요한
증거는 남습니다.

### 일반 설정

- **검사 주기(분)** — 기본 60분
- **전역 모의실행** — 켜져 있으면 개별 프로파일 설정과 무관하게 **아무것도 삭제하지 않습니다.** 기본값은 켜짐
- 프로그램 시작 직후 1회 실행 / Windows 로그온 시 자동 시작
- **정해진 시간대에만 정리 실행** — 아래 참조
- **용량이 부족하면 보관 기간보다 먼저 정리** — 아래 참조
- 여유 공간 경고·위험 기준(%)
- **사용량 추이 기록** / **검사기 공유 폴더** — 아래 참조
- 자체 로그 보관 기간

### 사용량 추이와 포화 시점 예측

`사용량 추이 기록` 을 켜면 1시간마다 여유 공간을 한 줄씩 남깁니다. 하루 24줄,
1년 모아도 수백 KB 수준입니다. **기본값은 꺼짐**입니다.

며칠 쌓이면 트레이 메뉴의 `사용량 추이` 에서 그래프와 예측을 볼 수 있습니다.

- 여유 공간 변화를 직선으로 맞춰 **하루당 순감소량**을 구합니다
- 정리 작업으로 계단식 회복이 섞여 있어도 "정리하고도 남는 증가분"이 기울기로 나옵니다
- **최근 7일**과 **최근 30일** 추세를 나란히 보여 줍니다. 7일이 30일보다 가파르면 최근 들어 급증한 것입니다
- 여유가 늘고 있으면 예측을 내지 않습니다

> 예측은 "지금 추세가 그대로 이어진다면"이라는 가정입니다. 생산량이 바뀌면
> 달라지므로, 정확한 날짜보다 **줄고 있는지 / 얼마나 빨리 줄고 있는지**를 보는 용도입니다.

### 검사기 현황 (다중 PC)

여러 검사기를 쓸 때, 각 PC가 자기 상태를 공유 폴더에 작은 JSON 한 개로 남기고
아무 PC에서나 전체를 모아 볼 수 있습니다. **서버나 데이터베이스를 설치하지 않습니다.**

`검사기 공유 폴더` 에 경로를 넣으면 켜집니다. **비워 두면 아무 동작도 하지 않습니다**(기본값).

```
\\서버\공유\DSM\dsm-status\INSP-01.json
                          \INSP-02.json
```

현황 창은 여유가 적은 PC를 위에 놓고, 3시간 넘게 보고가 없는 PC는 `연락 끊김` 으로
회색 표시합니다. 공유 폴더가 잠시 끊겨도 각 PC의 정리 작업은 그대로 돕니다.

### 실행 시간대

검사가 도는 시간에 대량 삭제가 겹치지 않도록, 정리를 허용할 시간대를 지정합니다.
`22:00 ~ 05:00` 처럼 자정을 넘겨도 됩니다.

시간대를 켜면 그 구간에서만 주기 실행이 일어나고, 구간 밖에서는 대기합니다.
**단, 여유 공간이 위험 기준 밑으로 떨어지면 시간대와 상관없이 즉시 정리합니다.**
용량이 꽉 차서 설비가 느려지는 것을 막는 게 이 프로그램의 목적이기 때문입니다.

### 용량 안전망 (긴급 정리)

기간 기준만으로는 생산량이 몰리는 달에 드라이브가 찰 수 있습니다. 그때 동작하는
최후 수단입니다.

```
평소            기간 기준으로만 정리
여유 < 위험(10%)  긴급 정리 발동
                 관리 폴더 목록 순서대로, 각 프로파일의 '긴급 시 최소 보관일'까지 삭제
                 여유가 경고 기준(20%)에 도달하면 즉시 중단
                 그래도 모자라면 더 지우지 않고 알림만 기록
```

**긴급 하한 아래로는 어떤 경우에도 내려가지 않습니다.** 하한까지 지워도 목표에
도달하지 못하면 프로그램이 알아서 더 지우는 대신 멈추고 기록을 남깁니다.
보관 기간 조정이나 저장소 증설은 사람이 판단할 일이기 때문입니다.

긴급 정리도 모의실행 설정을 따릅니다. 전역 모의실행이 켜져 있으면 대상만 기록합니다.

## 6. 안전장치

- 드라이브 루트(`D:\`), Windows·Program Files·ProgramData·AppData, 프로그램 자신의 폴더는 **등록 자체가 거부**됩니다
- 보호 폴더를 품고 있는 상위 경로도 거부됩니다
- 보관 기간 **최소 3일** 하한
- 심볼릭 링크와 정션은 따라가지 않습니다 (감시 폴더 밖으로 나가지 않음)
- 전역 모의실행이 기본값이며, 실제 삭제로 전환해 저장할 때 확인 창이 뜹니다
- 잠긴 파일은 건너뛰고 나머지를 계속 처리하며, 실패 건수를 기록합니다
- 중복 실행 방지 (뮤텍스)
- 설정 저장은 임시 파일 후 교체 방식이라 저장 중 정전에도 기존 설정이 남습니다

## 7. 자원 사용

검사 설비가 도는 PC에 상주하므로, 정리 작업이 설비를 방해하지 않도록 스스로를
낮은 자리에 둡니다.

| 장치 | 내용 |
|---|---|
| 프로세스 우선순위 | 기동 시 **BelowNormal** 로 내림 |
| 워커 스레드 | Windows **백그라운드 모드** — CPU뿐 아니라 **디스크 I/O 우선순위**까지 낮아져, 검사 프로그램이 이미지를 쓰는 동안 디스크를 선점하지 않음 |
| 메모리 | 삭제 후보를 리스트에 쌓지 않고 제너레이터로 처리. 정리 작업이 끝날 때마다 작업 세트 반납 |
| 유휴 시 깨어남 | 워커 2분 주기, UI 스레드는 창이 없을 때 0.6초 주기 |
| 트레이 갱신 | 표시 내용이 실제로 바뀐 경우에만 갱신 |

실측값 (Windows 11, Python 3.14, 프로파일 1개 상주):

```
우선순위    : BelowNormal
작업세트    : 20.9 MB
유휴 CPU    : 60초간 0.031초  (코어 1개 기준 0.05%)
스레드      : 6개
```

> 백그라운드 I/O 모드는 의도적으로 정리 속도를 양보합니다. 설비가 바쁠 때는
> 정리가 느려지는 대신 검사 작업이 밀리지 않습니다.

## 8. 로그

설정과 로그는 `%LOCALAPPDATA%\DiskSpaceManager\` 에 저장됩니다.
`DSM_DATA_DIR` 환경변수로 공용 경로를 지정하면 검사기 여러 대에 같은 설정을
배포할 수 있습니다.

```
config.json          설정
logs\app.log         동작 로그 (2MB x 5 회전)
audit\audit-YYYYMMDD.csv   삭제 이력
audit\alerts.csv     알림 기록
usage\usage-YYYYMM.csv     사용량 추이 (기록을 켠 경우)
```

### 알림

메일이나 메신저로 보내지 않고 **기록만 남깁니다.** `audit\alerts.csv` 에 모이고
동작 로그에도 경고로 남습니다. 상태 창 아래쪽에 가장 최근 알림 한 건이 보입니다.

남는 알림: 용량 위험 도달 · 긴급 정리 시작/완료/부족 · 시간대 예외 실행 · 삭제 실패 누적

> **`긴급 정리 부족`** 알림이 보이면 사람이 판단할 시점입니다. 하한까지 지워도
> 용량이 안 나온다는 뜻이므로, 보관 기간을 줄이거나 저장소를 늘려야 합니다.

설정창 `일반` 탭 아래쪽 버튼 세 개가 각각 이 폴더들을 탐색기로 엽니다.

| 버튼 | 여는 곳 | 언제 보나 |
|---|---|---|
| 설정 폴더 (config.json) | 데이터 폴더 전체 | 설정을 다른 검사기로 복사할 때 |
| 삭제 이력 (CSV) | `audit\` | 무엇이 언제 어떤 기준으로 지워졌는지 확인할 때 |
| 동작 로그 (app.log) | `logs\` | 프로그램이 제대로 돌았는지, 오류가 없었는지 볼 때 |

**감사 로그(CSV)** 는 `시각, 프로파일, 모드, 결과, 경로, 크기, 파일기준시각,
경과일, 날짜기준, 비고` 를 남깁니다. 실물 파일이 없어도 "그 날짜 이미지가
언제 어떤 기준으로 지워졌는지" 답할 수 있어야 하기 때문입니다.
엑셀에서 바로 열립니다(UTF-8 BOM).

모의실행 시 상세 행은 5,000건까지만 기록하고 나머지는 요약으로 남깁니다.

---

## 9. 도입 절차 (권장)

1. 검사기 **1대**에 설치하고 전역 모의실행을 켠 채 **2주** 운영
2. 감사 로그 CSV로 "지워질 뻔한 것"이 맞는지 검증 — 특히 불량 이미지가 대상에 없는지
3. 처리 방식을 **휴지통으로 이동**으로 바꿔 1주 운영
4. 문제 없으면 영구 삭제로 전환
5. 전 설비 확대 (`config.json` 복사 배포)

## 10. 개발 단계

**Phase 1 (완료)**
트레이 상주 · 폴더 프로파일 · 기간 기준 삭제 · 모의실행 · 감사 로그 · 설정창

**Phase 2 (완료)**
용량 임계치 기반 긴급 정리 · 실행 시간대 지정 · 알림 기록 · 프로파일 처리 순서

I/O 스로틀링은 워커 스레드를 Windows 백그라운드 모드로 돌리는 것으로 갈음했습니다.
초당 처리량 제한은 실제 검사기에서 측정한 뒤 필요하면 추가합니다.
PIN 보호 · NAS 아카이브 · 메일/웹훅 알림은 사용하지 않기로 했습니다.

**Phase 3 (완료)**
사용량 추이 그래프와 포화 시점 예측 · 다중 PC 현황

Phase 3 기능은 **전부 기본 꺼짐**입니다. 설정에서 켜야 동작합니다.
그래프는 tkinter Canvas 로 직접 그려 의존성을 늘리지 않았습니다.

않고 제너레이터로 흘려보내며 통계만 누적합니다.

### 화면 배율(DPI) 대응

검사기 PC는 해상도와 배율이 제각각입니다. tkinter 는 글꼴만 배율에 맞춰 키우고
코드에 적힌 픽셀 값은 그대로 쓰기 때문에, 창 크기·표 행 높이·여백을 모두
실제 배율로 환산합니다. 프로파일 편집 창은 내용 높이를 직접 계산해 크기를 정하고,
화면보다 길면 스크롤이 생기며 확인/취소 버튼은 항상 하단에 고정됩니다.

### exe 로 배포할 때

아이콘 파일을 함께 넣어야 합니다.

```bat
pyinstaller --noconsole --onefile ^
  --icon assets\app_icon.ico ^
  --add-data "assets;assets" ^
  DiskSpaceManager.py
```

`--icon` 은 exe 파일 자체의 아이콘, `--add-data` 는 실행 중 트레이·창에서 쓰는
아이콘입니다. 둘 다 필요합니다.
